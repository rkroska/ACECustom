Native Nether Fracture

Use the existing server installation and launcher. No new release layout, environment variable, database migration, replacement charm, or client plugin is required.

Production steps

  1. Back up the current complete server output, configuration and mod layout. Stop the server gracefully before building.
  2. Build the native branch using the existing workflow:
Set-Location C:\Scripting\ACECustom
dotnet build .\Source\ACE.Server\ACE.Server.csproj -c Release -p:Platform=x64 -m:1

Do not start if the build fails. Source Config/nether-fracture.json contains the enabled, tested five-zone profile and is copied to the normal build/publish output automatically. Do not copy another profile after every build. Keep existing Config.js, database settings, Pandemic charm levels and native ZC dials unchanged.

  1. Keep legacy BalanceBench.dll outside the entire scanned Mods directory. BalanceBench.TestOnly.dll is an optional observer/testing harness; neither mod is needed for production gameplay.
  2. Start once with the normal launcher. An existing ACE_NETHER_FRACTURE_CONFIG override takes precedence over the bundled file: if one is already configured, inspect that override before rollout. No new override is required.
  3. As a Developer/admin in each named zone, run /netherfracture show. Confirm enabled=True, the exact zone key, the values below and radius 5. Test three own direct DoTs then Nether Streak, priming/combat feedback, and a second caster. Check startup errors and normal login/combat.

Rollback

To disable the feature while keeping the new server, stop it, set Enabled to false in the source Config/nether-fracture.json, rebuild and start normally. If an external config override is already in use, disable that active file instead. This disables the entire feature, including its source scaling and independent stacking. Do not delete or corrupt the config: invalid hot reload retains the last valid settings.

For full rollback, stop, restore the complete backed-up output/configuration and prior mod layout, then start normally. Do not mix assemblies. Nether Fracture requires no database rollback.

Validation and limits

The native branch completed 209 main camps / 828 kills (two intentional T11-entry deaths), plus 90 accepted T13 comparison camps / 360 kills. One separate harness geometry incident/outside-trial death is documented in the QA report. The dependency rollback Release build and 90 selected regression tests passed. Enabling the source profile changes no balance coefficients or gameplay code.

Existing dependency security advisories remain unresolved; this is not a clean security certification. Confirm the actual production environment during rollout. No production deployment has been performed.

Compare production before changing underlying DoT settings

Run PRODUCTION-SETTINGS-READONLY.sql against production and return its complete result sets. It reads the existing ZC store, persisted ZC flags (including DoT spell math/landing tick) and Pandemic charm schedules. It writes nothing. Missing rows can mean code defaults. This export does not include the file-backed native Fracture profile: also capture /netherfracture show in each zone after the native code is installed.

Do not change shared Void multipliers, DoT multipliers, resistances, ranks or Pandemic schedules blindly, and do not apply the new Fracture coefficients to those older dials. Compare the export to the tested baseline first. A final list of additional production delta commands is pending that comparison; no claim is made that all existing production values match the test server.
